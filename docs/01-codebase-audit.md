# 01. 기존 코드베이스 점검

작성일: 2026-10-26 · 기준 커밋: `c6ced64`

## 무엇이 있나

| 파일 | 역할 |
|---|---|
| `index.html` (약 2,100줄, 160KB) | 앱 전체. HTML·CSS·바닐라 JS가 한 파일에 있다. 빌드 도구·프레임워크·패키지 없음. |
| `api/reading.js` | Vercel 서버리스 함수(Node, CommonJS). 클라이언트가 만든 `prompt`를 받아 Gemini(`gemini-3.1-flash-lite`)에 넘기고 JSON 리딩을 돌려준다. |
| `vercel.json` | `api/reading.js`는 `@vercel/node`, `index.html`은 정적 파일로 배포. 나머지 경로는 모두 `index.html`. |

## 현재 기능
- **카드 선택형 타로 리딩**: 사용자가 실제로 뽑은 카드를 4개 덱 탭(Universal Waite, Major Arcana, Lenormand, Oracle Belline)에서 골라 정·역방향을 지정 → 서버가 해석. 앱이 카드를 대신 뽑아주는 구조가 아니다.
- 스프레드 자동 판별(1/2/3/5/7/10장, 3:2:2 · 4:3:3 복합 리딩), "Starlight Guidance" 행동 제안.
- 리딩 기록: `localStorage`(`tarot_history_v1`, 최대 500건), JSON 내보내기·가져오기.
- 공유(`navigator.share`), 복사, 카드 상세 팝업, 사용 가이드.

## 새 기획과 비교했을 때 없는 것
- **서버 저장소(DB)가 없다.** 게시판·댓글·크레딧·신고는 모두 서버 DB가 필요하다.
- **로그인/계정이 없다.** 연령대·성별 표시, 크레딧, 차단은 계정이 있어야 한다.
- **사주 기능이 없다.** 타로만 있다. 사주는 생년월일시가 필요해서 개인정보 설계가 따로 필요하다 (`02-data-model.md` 참고).
- **기본/심층 리딩 구분과 결제가 없다.**
- **UI·리딩 출력이 영어다.** `<html lang="ko">`이고 카드명은 한국어 입력이지만, 화면 문구와 AI 출력은 모두 영어로 지정되어 있다. 타깃(한국 여성 사용자)과 맞는지 확인이 필요하다.

## 지금 코드에서 보이는 위험 (나중에 `/cso`에서 다시 볼 것)
1. **`/api/reading`이 누구에게나 열려 있다.** `Access-Control-Allow-Origin: *`, 인증·요청 제한 없음. 다른 사이트나 스크립트가 이 엔드포인트로 Gemini 사용량을 소모할 수 있다.
2. **클라이언트가 프롬프트 전체를 만든다.** 서버는 `prompt` 문자열을 그대로 모델에 넘긴다. 유료 심층 리딩을 붙이면 클라이언트가 심층용 지시를 직접 써서 보낼 수 있으므로, 서버가 리딩 종류를 판단하고 프롬프트를 조립해야 한다.
3. **에러 메시지를 그대로 노출한다.** Gemini 오류 문구가 사용자 화면까지 전달된다.
4. **설정 화면에 Gemini API 키를 `localStorage`에 저장하는 코드가 남아 있다** (숨김 버튼, 현재 서버 호출에는 쓰이지 않음). 정리 대상.
5. 리딩 결과를 `innerHTML`에 넣는 부분 일부(`c.deck`, `c.position`, `result.spread_used` 배지 외 summary 등)가 이스케이프 없이 들어간다. 지금은 AI 출력만 들어가지만, 게시판이 생겨 다른 사용자의 글이 화면에 나오면 XSS가 된다. 커뮤니티 화면은 처음부터 텍스트로만 렌더링해야 한다.

## AI 프롬프트 위치
- 리딩 시스템 프롬프트가 `api/reading.js` 안에 문자열로 박혀 있다. 기획 요구(프롬프트는 코드와 분리)에 따라, 새 기능 프롬프트는 `prompts/`에 둔다. 기존 리딩 프롬프트도 구현 단계에서 `prompts/reading.md`로 옮긴다 (배포 번들에 파일이 포함되는지 Vercel 설정 확인 후).

## 결론
기존 타로 리딩 화면은 그대로 살리고 그 위에 붙인다. 다만 커뮤니티 기능을 위해 **DB + 인증**을 새로 들여야 하고, 이 선택(무엇을 쓸지)은 오너 확인이 필요하다. 2,100줄짜리 단일 HTML에 게시판·댓글·신고 화면까지 넣으면 유지보수가 어려워지므로, 프런트 구조(바닐라 유지 vs. 프레임워크 도입)도 함께 정해야 한다.
